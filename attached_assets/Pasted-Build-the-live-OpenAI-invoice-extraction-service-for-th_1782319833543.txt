Build the live OpenAI invoice extraction service for the Invoice Data Extractor app.

Use OPENAI_API_KEY from Replit Secrets. Do not hard-code the key. Do not expose it to the client.

Use the OpenAI Responses API with a vision-capable model that can process PDF/image invoice inputs. If the app already has an OpenAI model configuration pattern, follow it. Otherwise add an environment-driven model setting such as OPENAI_MODEL with a safe default to a current vision-capable model.

Extraction input:
- Load the uploaded invoice file from the app’s existing object storage.
- Support PDF, JPG, JPEG, and PNG.
- For PDFs, send the file as a file input.
- For image files, send the image as a supported image input.
- Keep all OpenAI calls server-side only.

Extraction output:
Use Structured Outputs / JSON schema so the service returns predictable JSON.

Return this schema:
{
  "vendorRawName": "string or null",
  "invoiceNumber": "string or null",
  "invoiceDate": "YYYY-MM-DD or null",
  "dueDate": "YYYY-MM-DD or null",
  "paymentTerms": "string or null",
  "poNumberRaw": "string or null",
  "subtotal": "number or null",
  "taxAmount": "number or null",
  "freightAmount": "number or null",
  "invoiceTotal": "number or null",
  "amountDue": "number or null",
  "currency": "string, default USD unless invoice clearly shows another currency",
  "extractionConfidence": "number from 0 to 100",
  "fieldConfidence": {
    "vendorRawName": "number from 0 to 100",
    "invoiceNumber": "number from 0 to 100",
    "invoiceDate": "number from 0 to 100",
    "dueDate": "number from 0 to 100",
    "paymentTerms": "number from 0 to 100",
    "poNumberRaw": "number from 0 to 100",
    "subtotal": "number from 0 to 100",
    "taxAmount": "number from 0 to 100",
    "freightAmount": "number from 0 to 100",
    "invoiceTotal": "number from 0 to 100",
    "amountDue": "number from 0 to 100",
    "currency": "number from 0 to 100"
  },
  "lowConfidenceFields": ["array of field names below 85 confidence"],
  "extractionNotes": "brief note or null"
}

Extraction instructions:
- Extract accounts payable invoice header data only.
- Do not invent missing values.
- Use null when a field is not visible.
- Do not assign VendorID.
- VendorID must be looked up later from the controlled vendor table.
- Normalize dates to YYYY-MM-DD for database storage.
- Normalize amounts as numbers with two decimals.
- Currency should be USD unless another currency is clearly shown.
- Capture PO number if visible.
- Confidence scores must be 0 to 100.
- Low confidence threshold is 85.
- If multiple invoice totals appear, select the final amount due/total payable and explain briefly in extractionNotes.

Database/update requirements:
- Store extracted values on the invoice record using the app’s existing field names.
- Store overall extraction confidence.
- Store field-level confidence if the schema supports it.
- Store lowConfidenceFields if the schema supports it.
- Store full raw extraction JSON if the schema supports it.
- Preserve original uploaded file unchanged.

Workflow requirements:
- When extraction starts, set invoice status to extraction running or the closest existing status.
- After extraction completes, run Vendor_ID matching using vendorRawName.
- Then run validation.
- Route the invoice based on validation:
  - Clean invoice: move to Pending Approval or Ready for Approval status used by this app.
  - Missing required fields: route to Needs Review or Exception.
  - Vendor not found: route to Exception.
  - Vendor inactive/on hold: route to Exception.
  - Low extraction confidence below 85: route to Needs Review or Exception.
  - Duplicate VendorID + InvoiceNumber: route to Exception.
- Add clear error handling if OpenAI returns an error, file loading fails, JSON validation fails, or extraction times out.

Acceptance criteria:
- Uploading a real invoice PDF triggers OpenAI extraction.
- Uploading a JPG/PNG invoice triggers OpenAI extraction.
- Extracted fields populate the review screen.
- Extraction confidence displays as a percentage.
- VendorID is matched from the vendor table, not from OpenAI output.
- Validation runs after extraction.
- Exceptions route correctly.
- Raw extraction response is stored for troubleshooting/audit.
