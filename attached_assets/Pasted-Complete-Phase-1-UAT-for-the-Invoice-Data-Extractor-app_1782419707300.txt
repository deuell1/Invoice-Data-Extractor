Complete Phase 1 UAT for the Invoice Data Extractor app.

This is a read-only/testing and reporting task first. Do not rebuild the app or add Phase 2 features. Only fix defects that clearly block Phase 1 acceptance.

Goal:
Validate that Phase 1 is complete and ready for pilot use.

Phase 1 scope to validate:
- Upload PDF/image invoices
- Preserve original uploaded file
- Source document tracking
- Multi-invoice PDF detection
- One invoice_capture record per detected invoice
- Page range tracking
- Header extraction
- Field confidence capture
- Controlled Vendor ID matching
- Vendor autocomplete/search
- Validation rules
- Exception routing
- Review screen with document viewer and extracted data
- Previous/Next invoice navigation
- Bad upload void/remove
- Hard delete for test data
- Audit logging
- Approval workflow
- CSV export
- VoucherID / Posted workflow
- KPI dashboard counts

Do not include these in Phase 1 UAT:
- ERP posting automation
- Auto vendor creation
- Full three-way PO match
- Auto payment
- GL coding automation
- Vendor banking/remittance changes
- User permissions/role restrictions beyond what already exists
- Phase 2 analytics or dashboards

UAT test set:
Create or use a controlled UAT test pack with at least these cases:

1. Clean single-invoice PDF
Expected:
- Upload succeeds
- One source document is created
- One invoice record is created
- Original document remains viewable
- Header fields extract
- Vendor is matched or selectable
- Validation passes or gives explainable warning
- Invoice can be approved
- CSV export includes the invoice
- VoucherID can be entered only after approval
- Invoice moves to Posted

2. Clean image invoice
Expected:
- Upload succeeds
- One invoice record is created
- Image displays in document viewer
- Header fields extract
- Vendor matching and review workflow function

3. Multi-invoice PDF, same vendor
Expected:
- One source document is created
- Multiple invoice records are created
- Each invoice has invoiceSequence
- Each invoice has pageStart and pageEnd
- Each invoice extracts separately
- Previous/Next invoice navigation updates both document viewer and extracted data
- Each invoice can be approved/exported/posted independently

4. Multi-invoice PDF, different vendors
Expected:
- One source document is created
- Multiple invoice records are created
- Each invoice gets its own vendor match
- Vendor autocomplete works independently for each invoice
- No extracted data crosses between invoice records

5. Unknown vendor invoice
Expected:
- VendorRawName extracts if visible
- No controlled VendorID is assigned automatically
- Invoice routes to exception or needs review
- Vendor autocomplete allows manual selection
- Validation reruns after vendor selection

6. Missing vendor name or unreadable vendor
Expected:
- Invoice is flagged
- Exception reason is clear, such as Vendor Name Not Extracted
- Approval is blocked until corrected

7. Duplicate invoice
Expected:
- Duplicate detection triggers using VendorID + InvoiceNumber
- Duplicate is blocked or routed as expected
- Duplicate warning references the matched invoice record

8. Low-confidence / bad scan invoice
Expected:
- Field confidence is visible
- Low-confidence fields are highlighted
- Invoice routes to Needs Review or Exception
- AP reviewer can manually correct fields
- Audit log captures edits

9. Bad upload cleanup
Expected:
- Invoice can be voided/removed with a required reason
- Removed invoice disappears from active queues
- Removed invoice does not appear in approval queue
- Removed invoice does not appear in standard export
- Removed invoice does not affect active KPI counts
- Removed records can still be viewed with the appropriate filter/toggle if available
- Hard delete works for test data after confirmation
- Posted invoices cannot be hard deleted by default

10. Source document cleanup
Expected:
- A source document can be removed with a reason
- Child invoices are voided/removed
- A source document can be hard deleted for test data if no posted child invoices exist
- Source document deletion does not orphan invoice/audit records
- Stored file deletion is handled safely

11. Approval control
Expected:
- Invoice cannot be posted without approval
- VoucherID cannot be entered before approval
- Approved invoice can receive VoucherID
- VoucherID format such as V-12345 is accepted
- Posted invoice cannot be moved by general status change

12. CSV export
Expected:
- Export returns one row per invoice_capture record
- Multi-invoice source files produce multiple export rows
- Export includes SourceDocumentID, InvoiceSequence, PageStart, PageEnd, DocumentID, BusinessDocumentID, VendorID, InvoiceNumber, InvoiceTotal, Status, VoucherID
- Voided/removed invoices are excluded by default
- CSV values are safe for Excel/formula injection

13. KPI dashboard
Expected:
- Counts reflect active invoices only
- Voided/removed invoices are excluded from operational KPI counts
- Exception count is accurate
- Pending extraction count is accurate
- Needs review count is accurate
- Posted/approved counts are accurate if displayed

Vendor autocomplete UAT:
Specifically validate:
- User can type in the Vendor field
- Vendor list filters as the user types
- Vendor name is searchable
- Vendor code is searchable
- Vendor alias is searchable
- Extracted VendorRawName influences suggested matches
- Dropdown is scrollable with many vendors
- Selecting vendor saves controlled VendorID
- Selecting vendor reruns validation
- OCR/extraction never directly assigns VendorID without controlled lookup

Review screen UAT:
Specifically validate:
- Document viewer stays visible next to extracted data
- Image/PDF loads inline in Edge and Chrome
- Previous/Next invoice navigation is smooth enough for AP review
- Extracted data changes when invoice changes
- Validation messages change when invoice changes
- Audit log changes when invoice changes
- Edits save to the selected invoice only
- Re-run extraction applies only to the selected invoice
- Re-run vendor match applies only to the selected invoice

Acceptance metrics:
Track the following for each test invoice:
- Source file name
- Test case number
- Expected invoice count
- Actual invoice count
- Expected page range
- Actual page range
- VendorRawName extracted correctly: Yes/No
- VendorID matched correctly: Yes/No
- Invoice number extracted correctly: Yes/No
- Invoice date extracted correctly: Yes/No
- Due date/payment terms extracted correctly: Yes/No
- Invoice total extracted correctly: Yes/No
- PO number extracted correctly, if present: Yes/No/Not applicable
- Confidence score
- Exception reason, if any
- Manual corrections required
- Approval result
- Export result
- VoucherID result
- Defect notes

Phase 1 pass/fail thresholds:
- At least 80% of required header fields are extracted correctly across the UAT pack.
- 100% of invoices with unknown/missing vendor are routed to review or exception.
- 100% of duplicate invoices are flagged or blocked.
- 100% of approved invoices export correctly.
- 100% of posted invoices require prior approval.
- 100% of bad uploads can be voided/removed or hard deleted when appropriate.
- Multi-invoice PDFs produce one invoice record per invoice.
- No invoice record shows extracted data from a different invoice.
- No voided/removed invoice appears in standard active queues, standard export, or active KPI counts.

Defect classification:
Use these severity levels:

Critical:
- Wrong vendor, wrong amount, or wrong invoice number can be approved/exported without warning
- Extracted data from one invoice appears on another invoice
- Multi-invoice file combines multiple invoices into one payable record
- Duplicate invoice can be approved without warning
- Invoice can be posted without approval
- Bad data cannot be removed from active workflow

High:
- Vendor autocomplete does not work
- Document viewer does not display inline
- Extraction fails without clear error
- CSV export omits required fields
- Exception queue hides records that need review
- KPI counts are materially wrong

Medium:
- Slow/clunky navigation but data remains correct
- Minor UI confusion
- Non-critical field formatting issue
- Missing helper text

Low:
- Cosmetic issue
- Label/spacing issue
- Minor wording improvement
