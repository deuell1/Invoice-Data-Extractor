Fix the Vendor Master import template download issue in the Invoice Data Extractor app.

Do not rebuild the app. Do not remove existing Phase 1 or Phase 2 functionality. Do not delete invoices, vendors, source documents, import history, export history, or audit history. Do not add ERP integration.

Problem:
During Phase 2 UAT, the Vendor Master import template cannot be downloaded from the Imports page. This blocks vendor import testing.

UAT defect:

* Defect ID: UAT-VEND-IMPORT-001
* Area: Vendor Master Import
* Severity: High
* Issue: Vendor import template cannot be downloaded.
* Expected: User can select Vendor Master import and download a valid CSV template.
* Actual: Template download fails, does nothing, or produces no usable CSV file.

Required diagnosis:

1. Inspect the Imports page template download button/action.
2. Confirm the Vendor Master import type value sent by the UI matches the backend expected value.
3. Confirm the frontend calls the correct template endpoint.
4. Confirm the backend template endpoint exists and supports Vendor Master imports.
5. Confirm the backend response returns CSV content, not JSON, for successful template downloads.
6. Confirm response headers include:

   * Content-Type: text/csv or text/csv; charset=utf-8
   * Content-Disposition: attachment; filename="vendor-master-template.csv"
7. Confirm failed template requests return a clear JSON error with non-2xx status.
8. Confirm the frontend does not pass JSON, undefined, or a Response object into URL.createObjectURL.
9. Confirm browser download behavior works from the Imports page.

Functional requirements:

1. User can select Vendor Master as the import type.
2. User can click Download Template.
3. Browser downloads a CSV file.
4. File name should be clear, such as:
   vendor-master-template.csv
5. CSV must include headers accepted by the backend Vendor Master parser.
6. CSV must support minimal import with:

   * VendorID or VendorCode
   * VendorName
7. CSV must also include optional expanded vendor profile fields where supported:

   * LegalName
   * DBA / TradeName
   * VendorAliases
   * Address Line 1
   * Address Line 2
   * City
   * State / Province
   * Postal Code
   * Country
   * Main Phone
   * AP Email
   * Remittance Email
   * Website
   * TaxID / EIN
   * PaymentTerms
   * TermsDays
   * Currency default
   * VendorCategory
   * VendorType
   * IsActive
   * OnHold
   * HoldReason
   * RequiresPO
   * DefaultPORequired
   * Notes
8. Template should include at least one sample row or a clearly documented example row if the current import workflow supports samples.
9. The generated template headers must match the backend import parser exactly, or the parser must normalize documented header aliases.

Frontend requirements:

1. Add or repair the Vendor Master template download button.
2. Show loading state while downloading.
3. Show a visible error if download fails.
4. Use Blob download handling correctly:

   * fetch the endpoint
   * if response is not ok, parse/display the error
   * if response is ok, call response.blob()
   * pass only the Blob to URL.createObjectURL
   * trigger browser download
   * revoke the object URL afterward
5. Preserve the backend-provided filename from Content-Disposition when available.
6. Use a safe fallback filename if missing.

Backend requirements:

1. Ensure template endpoint supports Vendor Master import.
2. Ensure it returns CSV directly for successful requests.
3. Ensure invalid import types return a clear error.
4. Ensure template headers match the Vendor Master validation/commit parser.
5. Do not require Uploaded By / actor just to download a template. Actor should only be required for validation/commit actions if currently designed that way.

Regression checks:
After fixing, verify:

1. Vendor Master template downloads successfully.
2. Downloaded file opens as CSV.
3. Template headers match backend validation.
4. Minimal Vendor Master import using the downloaded template validates successfully.
5. Expanded Vendor Master import using the downloaded template validates successfully.
6. Missing VendorID/VendorCode produces row-level error.
7. Missing VendorName produces row-level error.
8. Existing vendor import commit behavior still requires actor/uploadedBy.
9. Existing vendor import history still works.
10. Vendor profile edit still works.
11. Vendor cleanup still works.
12. Export download still works.
13. No ERP functionality is added.

Deliverable:
Provide a concise fix report covering:

1. Root cause of template download failure.
2. Frontend changes made.
3. Backend changes made.
4. Final Vendor Master template headers.
5. Download behavior verification.
6. Import validation smoke test results.
7. Regression checks performed.
8. Remaining risks or manual UAT steps.
