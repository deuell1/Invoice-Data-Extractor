Required UAT test coverage:

1. Upload and source document handling
Validate:
- PDF upload succeeds
- JPG/PNG upload succeeds
- Original uploaded file is preserved
- Source document record is created
- Source document shows processing status
- Source document shows detected invoice count
- Uploaded file remains viewable from review screen

2. Multi-invoice detection
Validate:
- Single-invoice PDF creates one invoice_capture record
- Multi-invoice PDF creates one invoice_capture record per invoice
- Each invoice has sourceDocumentId
- Each invoice has invoiceSequence
- Each invoice has pageStart and pageEnd
- Different invoices from the same source can be reviewed independently
- Previous/Next invoice navigation keeps preview and extracted data synchronized
- No extracted data from one invoice appears on another invoice

3. Extraction accuracy
Use a controlled test pack of real or representative invoices.
Track required header fields:
- VendorRawName
- InvoiceNumber
- InvoiceDate
- DueDate or PaymentTerms
- PONumber, if present
- Subtotal, if present
- TaxAmount, if present
- FreightAmount, if present
- TotalAmount
- Currency
- ConfidenceScore
- FieldConfidence

Calculate:
- Total required fields tested
- Fields extracted correctly
- Fields requiring manual correction
- Extraction accuracy percentage
- VendorRawName accuracy
- InvoiceNumber accuracy
- Date accuracy
- Amount accuracy
- PO accuracy where applicable

Pass threshold:
- At least 80% of required header fields must be extracted correctly across the UAT pack.

4. Vendor matching and autocomplete
Validate:
- VendorRawName is extracted from invoice when visible
- VendorID is matched only from the controlled vendor table
- OCR/OpenAI output never directly assigns VendorID
- Unknown vendors route to exception or needs review
- Vendor autocomplete lets the user type into the vendor field
- Vendor autocomplete searches vendor name
- Vendor autocomplete searches vendor code
- Vendor autocomplete searches vendor aliases
- Extracted VendorRawName influences suggested matches
- Vendor dropdown is scrollable with many vendors
- Selecting a vendor saves controlled VendorID
- Selecting a vendor reruns validation
- Audit log records manual vendor edits

5. D2 duplicate guard validation
Validate the duplicate guard closes the intake gap.

Test cases:
A. Existing invoice has VendorID + InvoiceNumber.
Upload a new invoice where vendorId is initially blank, but VendorRawName resolves to the same controlled vendor and InvoiceNumber is the same.
Expected:
- Duplicate is detected
- Invoice routes to exception or duplicate-blocked state
- Approval/export/posting is blocked unless handled by existing duplicate override rules
- Message says: “Duplicate invoice detected for this vendor and invoice number.”

B. VendorRawName is similar but not confidently resolved.
Expected:
- Possible duplicate warning appears if invoice number and vendor name are similar
- It does not auto-assign VendorID
- It does not create a false confirmed duplicate unless match threshold is met

C. Voided/removed invoice has same VendorID + InvoiceNumber.
Expected:
- Voided/removed invoice is ignored by default for duplicate blocking

D. Multi-invoice PDF contains one duplicate and one clean invoice.
Expected:
- Duplicate invoice is flagged independently
- Clean invoice can proceed independently

6. Validation and exception routing
Validate:
- Missing VendorRawName routes correctly
- Vendor not found routes correctly
- Low vendor match confidence routes correctly
- Missing invoice number blocks approval
- Missing/invalid invoice date blocks approval
- Missing/invalid total amount blocks approval
- Duplicate invoice blocks approval
- Low extraction confidence creates Needs Review or appropriate warning
- Exception reason is clear and user-readable

7. Review screen
Validate:
- Document preview appears beside extracted data
- PDF preview works
- JPG/PNG preview works
- Multi-invoice PDF opens to the relevant page range
- Previous/Next invoice changes both preview and extracted data
- Save actions apply only to the selected invoice
- Re-run extraction applies only to selected invoice
- Re-run vendor match applies only to selected invoice
- Audit log updates for the selected invoice
- No stale data remains visible after invoice switching

8. Microsoft Edge inline rendering

- PDF invoice renders inline in the document viewer
- JPG invoice renders inline
- PNG invoice renders inline
- Multi-invoice PDF review displays or jumps to the correct page
- Open/download buttons remain available as secondary fallback controls
- Review can be completed without opening the document in a separate tab

If Edge fails:
- Fix preview headers or viewer behavior
- Keep files private
- Do not expose signed URLs in the UI
- Preserve server-proxy access for private storage

9. Bad upload cleanup
Validate:
- Invoice can be voided/removed with a required reason
- Voided/removed invoice leaves active queues
- Voided/removed invoice is excluded from standard export
- Voided/removed invoice is excluded from active KPI counts
- Voided/removed invoice is ignored by duplicate detection by default
- Removed records can be viewed when show-removed filter/toggle is used
- Hard delete works for test data only with confirmation
- Posted invoices cannot be hard deleted by default
- Source document remove voids/removes child invoices
- Source document hard delete removes child invoices/audit records safely when allowed
- Stored file deletion is safe and does not delete a file still referenced by another record

10. D4 list-level Export CSV validation
Validate:
- Invoice list has visible “Export CSV” button
- User can export approved invoices from list page
- User can export posted invoices from list page if supported
- Export shows loading state
- Export shows error if failed

- CSV contains one row per invoice_capture record

- CSV includes SourceDocumentID, InvoiceSequence, PageStart, PageEnd, DocumentID, BusinessDocumentID, VendorID, InvoiceNumber, TotalAmount, Status, VoucherID

11. Approval and VoucherID posting

Defect severity definitions:

Critical:
- Wrong vendor, wrong amount, or wrong invoice number can be approved/exported without warning
- Extracted data from one invoice appears on another invoice
- Multi-invoice PDF combines separate invoices into one payable record
- Duplicate invoice can be approved without warning
- Invoice can be posted without approval
- Bad data cannot be removed from active workflow

High:
- Vendor autocomplete/search does not work
- Duplicate guard does not evaluate VendorRawName-resolved vendor
- Export CSV button is missing or export fails
- Document viewer does not render inline in Edge
- Exception queue hides invoices that need review
- Validation does not block required fields
- KPI counts are materially wrong

Medium:
- Slow navigation but data remains correct
- Minor field formatting issue
- Non-critical export column issue
- Confusing user message

Low:
- Cosmetic issue
- Wording improvement
- Minor spacing/layout issue
