Create a safe vendor cleanup utility for the Invoice Data Extractor app to clear vendors that have been imported so far.

Do not rebuild the app. Do not delete invoices. Do not delete source documents. Do not remove Phase 1 or Phase 2 functionality. Do not add ERP integration.

Goal:
Clear vendor records that were imported during testing or pilot setup while protecting any vendor records that are referenced by invoices, audit history, import history, or other application records.

Important:
This must be a controlled cleanup process, not a blind delete. The app must prevent deletion of vendors that are already referenced by invoices unless a safe deactivation option is used.

Cleanup scope:

* Imported vendors only.
* Vendors created by vendor master import batches.
* Vendors with an importBatchId or LastImportedAt value.
* Vendors that were loaded through test/demo import workflows.
* Do not remove seed/system vendors unless they are clearly part of the imported test data and are not referenced.
* Do not remove vendors that have invoice history unless the action is to deactivate, not delete.

Required behavior:

1. Add a vendor cleanup / reset action

Add an internal admin-only cleanup action that can:

* Preview imported vendors before removal.
* Show how many imported vendors exist.
* Show how many are safe to delete.
* Show how many are referenced and cannot be deleted.
* Show how many will be deactivated instead of deleted, if selected.

2. Add preview mode first

Before committing cleanup, provide a preview showing:

* VendorID / VendorCode
* VendorName
* ImportBatchId
* LastImportedAt
* IsActive
* OnHold
* Invoice reference count
* Whether the vendor can be deleted
* Whether the vendor must be retained
* Recommended action:

  * Delete
  * Deactivate
  * Keep

3. Safe deletion rules

A vendor may be permanently deleted only if:

* It was imported.
* It is not referenced by any invoice.
* It is not referenced by any source document.
* It is not referenced by any required audit/event/history table that would break referential integrity.
* It is not required as seed data.
* It has no active dependency.

4. Referenced vendor rules

If an imported vendor is referenced by invoices:

* Do not delete it.
* Allow an option to mark it inactive instead.
* Preserve VendorID/VendorCode and VendorName so existing invoice history remains readable.
* Write an audit event noting the cleanup/deactivation action.

5. Cleanup options

Support these cleanup modes:

Mode A — Preview only

* No data changes.
* Shows cleanup plan.

Mode B — Delete safe imported vendors only

* Deletes imported vendors with no references.
* Keeps referenced vendors unchanged.

Mode C — Delete safe imported vendors and deactivate referenced imported vendors

* Deletes imported vendors with no references.
* Sets referenced imported vendors to inactive.
* Adds a note such as “Deactivated during imported vendor cleanup.”
* Requires identified actor and reason.

Mode D — Full vendor test reset

* Only available if all affected vendors are unreferenced.
* If any imported vendor is referenced, block full reset and show which vendors prevent reset.

6. Required controls

Require:

* Identified actor / user name
* Cleanup reason
* Confirmation checkbox or explicit confirmation text
* Preview before commit

Do not allow cleanup without:

* Actor
* Reason
* Confirmation
* Preview result

7. Audit logging

Record cleanup activity:

* Action type
* Actor
* Timestamp
* Cleanup mode
* Reason
* Vendor count reviewed
* Vendor count deleted
* Vendor count deactivated
* Vendor count skipped
* Per-vendor action details

Audit each vendor changed:

* VendorID/VendorCode
* VendorName
* Old status
* New status
* Deleted/deactivated/skipped
* Reason

8. Import batch cleanup

If imported vendors are deleted:

* Preserve import batch history if needed for audit.
* Mark affected import batches as cleaned or partially cleaned.
* Do not delete import batch records if doing so would remove required audit evidence.
* Show import batch cleanup status:

  * Active
  * Fully cleaned
  * Partially cleaned
  * Retained due to references

9. UI requirements

Add a safe internal page or section:

* Vendor Cleanup
* Imported Vendor Reset
* Cleanup Preview
* Cleanup History

The page should include:

* Cleanup mode selector
* Actor field
* Reason field
* Preview button
* Confirm cleanup button
* Results table
* Cleanup history table
* Clear warning that referenced vendors will not be deleted

10. API requirements

Add safe endpoints as needed:

* Preview imported vendor cleanup
* Commit imported vendor cleanup
* List vendor cleanup history

All endpoints must:

* Validate actor and reason.
* Default to preview/no-op behavior unless commit is explicit.
* Use transactions for commit.
* Return detailed results.
* Never delete referenced vendors accidentally.

11. Database safety

Before deleting any vendor:

* Check invoice references.
* Check audit/event/history references.
* Check import/export references.
* Check any foreign key dependencies.
* Use a transaction.
* Roll back on error.
* Return a detailed error if cleanup cannot complete.

12. Regression checks

After implementation, verify:

* Existing invoices still load.
* Existing invoice vendor references still display correctly.
* Vendor combobox still works.
* Vendor matching still works.
* Vendor import still works.
* Vendor profile editing still works.
* Vendor analytics still works.
* Export workflows still work.
* Dashboard metrics still work.
* No invoice records were deleted.
* No source documents were deleted.
* No ERP functionality was added.

13. Deliverable

Provide a concise implementation report with:

* What cleanup modes were added.
* What vendors are considered imported.
* What deletion safeguards exist.
* What happens to referenced vendors.
* What audit logs are created.
* What regression checks were performed.
* Whether the cleanup utility is ready for UAT.

Important:
Do not execute a destructive cleanup automatically as part of implementation. Build the controlled cleanup workflow first. Any actual cleanup should require preview, actor, reason, and explicit confirmation.
