Apply these two Phase 1 requirement corrections to the Invoice Data Extractor app.

Do not rebuild the app from scratch. Preserve the existing extraction, vendor matching, validation, review, audit log, exception queue, approval, export, and VoucherID workflows.

Correction 1 — Vendor extraction/match must always flag invoice

Requirement:
An invoice must always be flagged for AP review or exception if:
1. VendorRawName / extracted vendor name is blank, null, or not extracted.
2. VendorRawName is extracted but no Vendor_ID match is found in the controlled vendor table.
3. Vendor match score is below the configured threshold, currently 85%.
4. Matched vendor is inactive or on hold.

Implementation requirements:
- After extraction, run validation before allowing approval.
- If VendorRawName is missing:
  - Set ReviewStatus or Status to Exception or Needs Review, using the app’s existing status model.
  - Set ExceptionReason to “Vendor Name Not Extracted”.
  - Block approval until corrected.
- If VendorRawName exists but no Vendor_ID match is found:
  - Set ReviewStatus or Status to Exception.
  - Set ExceptionReason to “Vendor Not Found”.
  - Block approval until corrected.
- If VendorMatchScore is below 85:
  - Set ReviewStatus or Status to Needs Review or Exception.
  - Set ExceptionReason to “Low Vendor Match Confidence”.
- If matched vendor is inactive:
  - Set ReviewStatus or Status to Exception.
  - Set ExceptionReason to “Vendor Inactive”.
- If matched vendor is on hold:
  - Set ReviewStatus or Status to Exception.
  - Set ExceptionReason to “Vendor On Hold”.
- These rules must run after:
  - Initial extraction
  - Re-run extraction
  - Manual field edits
  - Vendor rematch
  - Submit for approval
  - Approve action
- Approval must be blocked when VendorRawName is missing or Vendor_ID match is missing.
- Show the vendor issue clearly on the Extraction Review screen and Exception Queue.
- Add or update tests/manual QA notes for:
  - Missing vendor name
  - Unknown vendor
  - Low vendor match confidence
  - Vendor inactive
  - Vendor on hold

Correction 2 — DocumentID format

Requirement:
Document ID should be formatted as:

Vendor ID - Invoice Number - Invoice Amount

Example:
V-00123 - INV-12345 - 1309.00

Implementation requirements:
- Once VendorID, InvoiceNumber, and InvoiceTotal are available, generate/update the displayed DocumentID using this format:
  VendorID + " - " + InvoiceNumber + " - " + InvoiceTotal
- Invoice amount should be formatted as a numeric amount with two decimals and no dollar sign in the DocumentID.
- Use the matched VendorID from the controlled vendor table, not OCR/OpenAI output.
- If VendorID is not available because vendor matching failed, do not create a false VendorID.
- If the invoice has not yet been extracted or matched, use a temporary internal ID for database uniqueness and file storage.
- Preserve the original internal unique invoice record ID for database relationships, audit logs, file storage paths, and system references.
- Treat this formatted DocumentID as the business-facing DocumentID/display ID.
- Ensure the formatted DocumentID is updated after:
  - Extraction completes
  - Vendor match completes
  - AP manually corrects VendorID
  - AP manually corrects InvoiceNumber
  - AP manually corrects InvoiceTotal
- Prevent duplicate business DocumentIDs. If the same VendorID + InvoiceNumber + InvoiceTotal already exists, route to Exception with Duplicate Invoice or Duplicate DocumentID warning.
- Update UI labels where appropriate so users see the business-facing DocumentID.
- Update CSV export to include this formatted DocumentID.
- Keep existing internal ID if needed as InternalInvoiceID or system ID.

Important control:
Do not use this formatted DocumentID as the only primary key if changing it would break audit logs, file links, or related records. Keep a stable internal ID and add/update a separate business-facing DocumentID field if needed.

Acceptance criteria:
- Invoice with missing vendor name is flagged and cannot be approved.
- Invoice with vendor name but no Vendor_ID match is flagged and cannot be approved.
- Invoice with active matched vendor displays DocumentID like “V-00123 - INV-12345 - 1309.00”.
- Revisions to VendorID, InvoiceNumber, or InvoiceTotal update the displayed DocumentID.
- CSV export includes the formatted DocumentID.
- Existing audit log and file links remain intact.
