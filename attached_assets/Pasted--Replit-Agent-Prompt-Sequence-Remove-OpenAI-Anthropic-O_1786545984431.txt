## P0 — Fix the malformed env values (do this yourself, no agent)

`.replit` currently contains:

```
[userenv.shared]
ANTHROPIC_MODEL = "claude-haiku-4-5-20251001"
EXTRACTION_PROVIDER = "EXTRACTION_PROVIDER=anthropic"
ANTHROPIC_TIMEOUT_MS = "ANTHROPIC_TIMEOUT_MS=60000"
```

The variable name is pasted inside the value on two of the three. At runtime:

| Var | Actual value | Effect |
|---|---|---|
| `EXTRACTION_PROVIDER` | `"EXTRACTION_PROVIDER=anthropic"` | ≠ `"anthropic"` → **falls through to the OpenAI branch** |
| `ANTHROPIC_TIMEOUT_MS` | `"ANTHROPIC_TIMEOUT_MS=60000"` | `Number()` → `NaN` → lands on the 60000 default by luck |
| `ANTHROPIC_MODEL` | correct | fine |

Change to:

```
[userenv.shared]
ANTHROPIC_MODEL = "claude-haiku-4-5-20251001"
EXTRACTION_PROVIDER = "anthropic"
ANTHROPIC_TIMEOUT_MS = "60000"
```

Restart the API. Do this first — it costs nothing and it is very likely the root cause of the provider confusion.

## P1 — Make the silent mock fallback fail loudly

**Why:** `extractionService.ts:850` sets `usingMock = !isExtractionConfigured()`. Missing key → `mockExtract()` (line 135) writes seeded, fabricated vendor names and amounts to `invoice_capture` with no error. Combined with P0's typo, this is how a run can look fine and mean nothing.

### Prompt

```
In artifacts/api-server/src/services/extractionService.ts, the extraction runner
falls back to mockExtract() whenever isExtractionConfigured() returns false. That
silent fallback writes fabricated invoice data to invoice_capture and makes test
runs untrustworthy. Change it to fail closed, and make mock mode an explicit
developer opt-in.

Requirements:

1. Introduce EXTRACTION_MOCK_MODE. Mock extraction runs ONLY when
   process.env.EXTRACTION_MOCK_MODE === "true".

2. Rewrite provider selection at the extraction runner (around line 850):
   - EXTRACTION_MOCK_MODE === "true"  -> run mockExtract() as today
   - else if !isExtractionConfigured() -> throw ExtractionError with category
     "PROVIDER_ERROR" and message: "Extraction is not configured. The API key for
     the extraction provider is missing." Do not include any key material or env
     var values in the message.
   - else -> run the configured provider path as today

3. Make active mock mode unmistakable:
   - Log a warning per extraction via artifacts/api-server/src/lib/logger.ts,
     including the invoice id.
   - Prefix the invoice's extractionNotes with the literal "[MOCK MODE] ".

4. Add a boot-time log where startup logging already lives (app.ts or index.ts):
   log the resolved extraction provider, the resolved model name, and whether
   mock mode is on. Log the model NAME only. For the key, log only a boolean
   "configured: true/false" — never the value, never a prefix or suffix of it.

Do not change mockExtract()'s field generation. Do not change
isExtractionConfigured(). Do not touch the extraction functions themselves in
this prompt. Report the files you changed.
```

## P2 — Forced tool-use and stop_reason handling on the Anthropic path

**Why:** `anthropicStructured.ts` asks for raw JSON in the system prompt and strips markdown fences with a regex. No `tools`, no `input_schema`, no `tool_choice` exist anywhere in the repo, and no `stop_reason` check exists — a `max_tokens` truncation currently fails only incidentally when `JSON.parse` throws, miscategorized as `INVALID_RESPONSE`. `maxRetries` is 1, not the documented 2.

`.agents/memory/anthropic-port.md` states *"Strict JSON not native: append JSON-only instruction to system prompt for Claude since it doesn't enforce a schema natively."* **That is incorrect** — forced tool-use enforces the schema server-side. Correcting that belief is part of this prompt.

**This must land before P3.** After P3 there is no second provider to fall back on.

### Prompt

```
artifacts/api-server/src/services/anthropicStructured.ts asks the model for raw
JSON in a system prompt and strips markdown code fences from the text response.
Replace that with the Anthropic Messages API's forced tool-use mechanism, which
enforces the output schema server-side, and add explicit stop-reason handling.

Note: the project memory file .agents/memory/anthropic-port.md claims Claude
"doesn't enforce a schema natively." That is wrong — forced tool-use does.
Correct that line as part of this task.

Requirements:

1. Change callAnthropicStructured to take a JSON Schema. New signature:

   callAnthropicStructured(params: {
     systemPrompt: string;
     userContent: AnthropicUserContent;
     toolName: string;
     toolDescription: string;
     inputSchema: Record<string, unknown>;
   }): Promise<unknown>

2. Pass the schema as a single tool and force its use:
   tools: [{ name: params.toolName, description: params.toolDescription,
             input_schema: params.inputSchema }]
   tool_choice: { type: "tool", name: params.toolName }

3. Read the result from the tool_use content block's `input` field and return it
   as a parsed object. DELETE the markdown code-fence stripping regex entirely —
   it is unreachable now and its presence invites regression.

4. Check stop_reason explicitly BEFORE reading any content. Throw a distinct,
   descriptive Error for:
   - "max_tokens" -> output truncated; must never be parsed as a successful
     extraction
   - "refusal"    -> model declined; must fail loudly
   Any stop_reason other than "tool_use" (or "end_turn" when a tool_use block is
   nevertheless present) must throw rather than fall through.

5. If no tool_use block is present, throw. No text fallback.

6. Change maxRetries from 1 to 2.

7. Update callers — anthropicExtract() in extractionService.ts (around line 698)
   and detectPdfAnthropic() / detectImageAnthropic() in
   documentDetectionService.ts — to pass JSON Schemas equivalent to the field
   sets they currently request in prose.

   CRITICAL: the schema must describe the SAME fields with the SAME names and
   types the current prompts request. Do not add, rename, remove, or retype any
   extraction field. The extraction field names must continue to match the
   ground-truth CSV header exactly: vendorRawName, invoiceNumber, invoiceDate,
   dueDate, paymentTerms, poNumber, subtotal, taxAmount, freightAmount,
   totalAmount, currency (plus discountAmount and otherChargesAmount, which the
   tie-out logic depends on).

8. Preserve these prompt rules verbatim in meaning — they are hard-won:
   - vendorRawName and invoiceNumber are captured EXACTLY as printed: no
     normalization, no stripping of leading zeros, no substituting a trade name
     for a legal name.
   - A printed $0.00 is a zero, not a null.

9. Keep the SDK 0.116.0 error-shape notes at the top of the file
   (err.constructor.name, err.requestID) and leave the timeout and
   categorization behavior in extractionService.ts intact.

Report the files you changed and print the JSON Schemas you generated.
```


```
client-supplied identity, even as a fallback.

   (req as any).clerkUserId.

   lib/api-spec/openapi.yaml, then regenerate:
     pnpm --filter @workspace/api-spec run codegen
   Never hand-edit anything under lib/api-zod or lib/api-client-react.

4. Find every caller that sends `actor` in the remove request body — check
```
